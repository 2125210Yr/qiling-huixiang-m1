玩家从普通入口启动原创模式，不需要控制台、调试快捷键或源码目录。

## 3. 一章远征的确定流程

地图使用固定小图结构，不先接入大型程序化地图库。每个节点有唯一 `nodeId`；同层分支互斥，不能来回刷奖励。

| 节点 | 内容 | 选择与状态变化 |
|---|---|---|
| N0 据点 | 看五人基础职责，选择 A01／B01／C01 中一个核心 | 三个核心首局全可用；创建 runId、冻结内容版本与解锁快照 |
| N1 前厅 | 短普通战，认识点敌与主动技能 | 胜利后奖励 R1：三选一，至少一个是当前初始核心的合法后继 |
| N2 分岔 | 后台：较少耐打敌人；观众席：更多脆弱敌人 | 两边战前展示构成与奖励倾向；只打一边；胜利后 R2 |
| N3 工坊 | 在休整与强化之间选择 | 休整：存活队员恢复至至少 50% MaxHP，倒下队员以 35% MaxHP 恢复；强化：放弃此恢复，领取一次三选一 R3 |
| N4 排练厅 | 一场精英战，练习处理随从与可见群攻预警 | 胜利后 R4；满足家族前置时提供当前家族放大件，否则提供合法补件 |
| N5 返场回廊 | 一场普通多目标战，用于让成型构筑实际发挥 | 不追加新遗物；仅执行普通胜利恢复，随后进入首领前整备 |
| N6 首领门前 | 展示首领情报、现有构筑、主动技能和固定出场顺序 | 全队回满并恢复倒下角色；可以调整已拥有的基础配置；确认出战时冻结 BossCheckpoint |
| N7 白面指挥者 | 首领战 → 胜利结算，或原样重试／结束远征 | 首领死亡即允许结束，不强制播放剩余机制；奖励仅结算一次 |

N5 的意义不是填时长，而是给玩家至少一场“成型之后的战斗”。不能把放大件只安排到通关之后。

### 3.1 战斗之间保留什么

- 普通战之间保留当前生命与倒下状态；每场胜利让尚存活队员恢复 15% MaxHP，最多到上限。N3、N6 的恢复规则另按上表执行。
- 不跨场保留战斗护盾、减益、蓄能、充能、技能冷却或队伍爆发值；这些每场重新初始化。临时遗物本身保留至远征结束。
- 下一场开局生命是本次远征状态的正式输入，必须记录与回放；不可把它伪装成“开战后测试脚本改血”。
- 普通战或精英战全灭：该趟远征结束；可保留已提交的发现图鉴，但不发首通奖励。Boss 战全灭：进入专用原样重试入口。
- 普通战中退出／崩溃：下次回到该场已持久化的战前检查点；不做任意战斗中间帧续玩。这是公开的便利性设计，不额外开发防存档作弊。
- `Failed`（未实现效果、配置错误等工程失败）不能伪装成玩家败北；单独显示错误并保留检查点，不记关卡失败奖励。

## 4. 小队与操作：少做新系统，保留关键选择

### 4.1 五人功能配置

复用已有角色资源和五人 HUD；玩法数据使用本模式独立 ID，不能写坏原 C001… 数据。工程师须提供最小原创／合成内容，不能再以“旧合同说角色技能由用户提供”为由停在空表。

建议五个职责：单体输出、守护、恢复、第二输出、增益辅助。不是五名必须重新制作立绘的新角色。

每个职责有基础自动行动和 1 个常用主动技能，已有 Tap／Slide 可以继续作为内部通道。首版只暴露每名队员一个主要技能按钮，第二套配置可在据点切换；不要求玩家同时掌握原 DC 的所有手势。

- 守护者至少有可覆盖全队的基础护盾；恢复者具备可用治疗；队伍至少两人具备单体直接伤害，保证 B 系核心有实际作用对象。
- 基础队伍即便没有稀有放大件，也应能用合法技能处理面具和群攻；不得把通关必需能力仅放在随机掉落里。
- 本版不使用未核验的反射、复活、穿防等原技能 opcode 假装“已经支持”。首领门前复原队员属于远征检查点准备，不等于实现通用战斗复活技能。

### 4.2 普攻自动，主动技能可控

当前 `AutoMode.Manual` 下普通自动攻击仍由 `TickUnit` 推进；`Full` 会拒绝部分玩家技能输入。[S04–S05] 新入口默认采用前者的所有权思路，不为“自动普攻”误开 Full Auto。

保留真实敌方点选、主要技能、暂停、恢复和 1×／2×。先不开放 3×，避免本版读条可读性额外负担。

**本版不要求 QTE、Fever 连点或新增队伍大招。** 新模式通过明确规则开关关闭这些流程、对应自动触发和专属教程；旧模式代码与样本保留。不得通过永远不显示 QTE 却让模拟继续等待的方式“隐藏功能”。

### 4.3 战术暂停的最小语义

暂停时世界时钟、敌方读条、冷却、状态、蓄能都不推进。玩家可以为不同角色各放入最多一条待执行指令，并选择集火目标；同一角色再次选择覆盖其旧指令，可清除。

恢复时：先提交恢复，再按确定的入队顺序处理待执行指令，然后才推进下一个模拟 tick。每条依旧通过统一 `Submit` 校验。

- 只执行恢复时合法且已就绪的指令，不自动等待冷却，不免费补充充能。
- 目标失效、角色死亡或资源被前一条消耗时，该条拒绝并显示原因；其余独立指令继续。
- 不用临时清掉 `Paused` 来偷偷施法；不由 HUD 直接调用 `Cast` 或改 HP。
- 回放记录已接受／拒绝的实际命令顺序；若保存暂停队列，只允许保存在当前会话显示层，不承诺战中持久化。

## 5. 首领：白面指挥者的机制合同

这些机制是新设计，不冒充现有实现或原作规则。正式数值放在配置中，以下是初始候选值。

### 5.1 固定单位与行为所有权

首领占敌方槽 0，面具占槽 1、2。两面具初始存活，不独立释放随机技能。首领使用专用行为调度；普通敌人继续走现有路径。

必须抑制该首领原 `TickUnit` 中会直接随机选择 Tap／Slide 的自动技能路径，避免“脚本放一次、旧逻辑又放一次”。首领普攻也只由一个明确所有者调度。[S05]

不为本版实现通用召唤与二十人战斗。面具仅使用这场遭遇的两个固定槽，并带实例代数，重建后旧待执行动作不能错误命中新实例。

### 5.2 两个核心机制

**共鸣面具：** 每个存活面具，使“终幕回响”的伤害乘数增加 0.5。结算时为 `1 + 0.5 × 存活面具数`。面具可被普通点敌与伤害击败；强化倍数在群攻实际结算时读取，所以读条期间清掉面具有用。

**终幕回响：** 首领提前公开群攻意图，初始读条候选 4.0 秒。到期后通过真实战斗结算执行一次群攻，不能由动画结束或 HUD 倒计时触发伤害。

- 群攻首次预告候选为战斗开始后 9 秒；每次群攻完成后，第一阶段间隔 10 秒再预告，第二阶段间隔 8 秒。
- 普通单体攻击间隔候选 3 秒；群攻读条期间不再插入额外首领普攻，完成后重新安排普攻计时。
- 读条 UI 读取模拟快照的剩余时间、目标范围与实时面具加成。不要显示冻结不变的“必定伤害”，因为清面具后结果会变。
- 暂停与技能政策停顿对首领读条使用同一个游戏时钟；表现动画不拥有第二套权威时间。

### 5.3 一次阶段变化

首领生命首次降到 50% 或以下，且仍存活时，标记进入第二阶段：最多补回两个面具，将后续群攻间隔改为第二阶段值，不恢复首领生命，不设置强制无敌。

阶段切换在当前原生动作与其受限连锁处理完成后的稳定边界发生。若正在读条，保留这次读条，切换效果延后至它完成；不能以切阶段把剩余读条变成零或多结算一次。

若这一轮连锁直接击杀首领：以“首领已死亡”为本场胜利条件，即使面具仍存活也不继续打空场。稳定结算边界若首领与全队同一动作链中同时倒下，本版记胜利；工程 Failed 优先于任何正常胜负。胜利后取消未完成意图、面具重建与新攻击。允许强构筑跳过阶段／后续循环，不用隐藏伤害上限维护演出长度。

### 5.4 允许的解法

至少实际验证：基础队伍优先清面具后应对；防护构筑保留技能承受带面具群攻；成型输出构筑缩短首领战。不是要求三者耗时相同。

首领不根据玩家持有的遗物临时调整抗性、偷偷加血或禁用流派。以后增加挑战变体必须事前可见，本版不做。

A 系震荡的力度直接作为本版衍生伤害的已计算值进入护盾／生命扣减，不再暴击或重复套攻击、防御与增伤；技能型放大必须在表中明确。这是有限的独立反击预算。A 系使用明确的本版衍生伤害入口：它不是把 `Reflect` 枚举改为已实现，也不是无条件百分比反射敌人原伤害。每场蓄能清零、阈值按冻结开局数据计算，不能跨场积攒再修改 MaxHP 套利。

| B02 折射刃 | 散射比例由 40% 改为 70%，不是再乘一次 1.7。 | B01 |

参考力度为该次原生施法首个有效主命中，在原目标防御与暴击等规则计算完成后、扣护盾／生命之前的伤害值；不得拿整技能总伤害再次按每次命中倍增。复制结果不二次暴击、不再次应用源增伤，也不重复套目标防御；仍按衍生目标护盾和剩余 HP 实际结算。它是明确设计的“复制打击力度”，不是通用穿防 opcode。

B 系仅服务单体直接伤害；原生群攻、持续伤害、反击震荡和其他衍生效果不触发。B04 的衍生击杀不能再引发回响或散射。

### 6.5 衍生伤害与触发顺序

先完成原生动作的所有命中、状态、护盾／生命变更，产生不可变结果，再按固定优先级处理衍生效果：A → B → C。一个 rootAction 只能处理一次各家族相应触发。

如实现需要不同的固定顺序，可以在编码前记录在 `RULES.md` 并写测试；不得随字典遍历、画面帧率或处理器调度改变。

首领死亡后不再产生新的敌方攻击或新的遗物伤害链。已计算出的展示可播放，不能继续发奖励或修改胜负。

配置域检查需保证合法内容在有界队列中结束。工程防护预算被触发时应记录规则错误并使测试失败，不能静默截断一次正常强力连锁再说“平衡成功”。不允许整数溢出、NaN、无穷、负治疗／负吸收。聚合统计至少使用 64 位计数，战斗值保持在已支持的数值域。

## 7. 奖励生成：可找方向，不把通关资格交给运气

N0 三个核心固定可选。R1、R2、R3、R4 是有约束三选一，不先做完整稀有度或概率经济。

- 每组选项尽量三个不同且本趟未持有的有效遗物。候选必须满足前置、家族与固定小队的能力要求。
- R1／R2 至少给出一个初始核心的合法后继，其余从有效通用池抽取，可包含另一家族核心。玩家可以主动混搭，也可以沿主线补齐。
- R4 若满足初始家族放大件前置，至少包含该放大件；不满足则至少包含能推进该家族的合法补件。不能发无法触发的高阶遗物。
- N2 路线只影响公开的候选倾向：后台偏 A／C，观众席偏 B／C；不修改 Boss 强弱。
- 没有三个合法候选时显示实际数量，不复制同一件伪造三个；极端无候选时给一次明确的休整替代，不无限重抽。
- 普通奖励允许放弃并获得一小次生命恢复，候选仍被消费；刷新／退出不得重抽。核心选择不能空缺。
- 候选在展示前生成并持久化；重新进入同一节点读原候选。点击选择携带 `offerId` 和 `expectedRevision`，重复点击只能提交一次。
- 随机流分离：路线／奖励、战斗各自独立。排序和种子派生稳定；不使用进程随机化 `GetHashCode` 或 UI 的随机调用影响奖励。
- 不根据战斗中玩家表现暗改未来奖励、怪物 HP 或抗性。

本版不追求几百种 Buff。可理解的组合、确实不同的选择和成型时间，比候选总数重要。

## 8. 成长与正反馈：需要看见的变化

### 8.1 永久与局内成长

永久：记录发现过的遗物与已通章节。首次完整通关，解锁一个**不提高预算的等价起始技能配置**，例如输出者可选“单体较强”或“多目标但单体较弱”，下次出发前切换。替代配置适配相应遗物池，不无脑稀释原池。

本版没有永久经验刷级、反复通关加基础攻击或抽卡养成。重复通关不给叠加数值，只更新可见战绩／图鉴。新一趟删除前一趟所有临时状态。

局内：N0 有立即生效的核心；N1／N2 补连接；N4 有放大机会；N5 和 N7 给组合发挥的战斗。不是最后领奖才首次成型。

### 8.2 数值候选与调参方法

初始体感目标可以采用普通战约 35–70 秒、首领常规构筑约 120–210 秒的游戏时间；这是候选区间，不是制作时限或质量事实。强构筑可以显著短于它，不为凑时长强制加血或锁阶段。

对同一固定测试场景、相同基础角色和输入策略，记录无遗物、普通混搭、家族成型、极端组合的效率。初始目标是至少有一个完整家族在适配场景产生清晰优势，例如有效输出或完成速度出现约 2 倍以上的变化；防护系还应看承伤、保护与恢复，不强求全部家族比同一 DPS 数字。

这些目标不用于给所有敌人同比扩血。测试场景固定，不读取玩家构筑后自动补偿。普通合法构筑可通关，成型构筑可以碾压部分普通战、减少首领循环。

初始伤害数学先复用当前可运行计算分支，**作为本模式明确采用的原型规则**，不承诺来自原 DC、也不在本版顺带重写全部 DamageMath。新入口记录 `rulesetId=original-expedition-v01` 和真实 `FormulaProfile`。当前 Heal／FireDot 有 profile 白名单，不能只给枚举新增名字而不处理这些路径。[S07] 如确需新公式，必须作为单独标注的有界改动，保持旧分支不被静默替换。

### 8.3 统计必须是真实结算

当前 `Stats.NoteDamage` 使用请求的 dmg，`NoteHeal` 使用请求治疗量，不能直接把它们当作新模式“实际贡献”的完整口径。[S07]

新模式在结算位置生成结构化 `ResolutionResult`，至少区分：

```text
原生／衍生、sourceId、rootActionId、技能／遗物ID、目标实例
请求伤害、实际护盾吸收、实际生命损失、溢出伤害
请求治疗、有效治疗、过量治疗
```

- 有效伤害 = 实际扣除的敌方生命＋实际消耗的敌方护盾；溢出单列，不重复相加。
- 连锁总伤害可以显示，但须注明是整次连锁／多目标合计，不冒充单次单体命中。
- A01 只计实际护盾吸收；治疗正反馈优先有效治疗，不靠反复对满血目标治疗刷数字。
- “避免死亡”等反事实结论只有在能用明确结算数据证明时才显示；本版不必实现，可显示真实吸收量。
- 每次关键遗物触发在 HUD 短暂亮起对应图标；A 显示蓄能、C 显示接力／和声进度、B 显示实际扩散目标。
- 结算展示三个最重要的事实及一个可执行提示，不输出大篇分析；不得调用模型编造归因。

## 9. 首领前检查点与永久存档：严格定义，不留模糊边界

### 9.1 原样重试

N6 整备完成并确认进入首领时，保存不可变 `BossCheckpoint`：基础配置、五人开局状态、所持遗物、派生战斗配置、首领版本、战斗 seed、内容与规则指纹。

失败后“原样重试”完整恢复这份输入，不恢复到失败时状态，不重新生成奖励，不改变地图，不重置首领为另一随机版本。新的 attemptId 只用于日志；重试仍使用同一个战斗 seed 和规则输入。

玩家可以改变操作顺序，所以结果可以不同；不能宣称“同 seed 无论怎么操作都得出相同结果”。若主动选择结束远征才清空本趟遗物，返回据点重新开始。MVP 不在检查点重试中开放购买、重抽或替换遗物。

### 9.2 单文件的一致性边界

优先将新模式的永久解锁、活动远征、候选、检查点、奖励领取标记和最近结算摘要放入**一份独立 profile 文件**，避免先写 run 再写 meta 的双文件半成功。

建议位置是现有本地数据目录下独立的 `OriginalExpedition/profile.v1.json`。实际根目录沿用已有安全路径工具；不要硬编码用户名，不读取或覆盖原 `save.json`。

建议状态字段（新规格，不是已实现类型）：

```text
OriginalProfile
  schemaVersion, revision, contentVersion
  unlockedPresets, discoveredRelics, clearedChapters
  activeRun?
    runId, runSeed, rulesetId, frozenContentHash, unlockSnapshot
    partyConfig, currentNode, visitedNodeIds, status
    partyHpAndDownState, ownedRelicIds
    pendingOffer?, selectedChoices, battleOrdinal
    currentBattleCheckpoint?, bossCheckpoint?
    settledBattleIds, resultApplied
  lastRunSummary?
```

`lastRunSummary` 可记录遗物名称与贡献供回看，但它不是下一趟开局输入。

### 9.3 写入与恢复语义

- 所有会改变资源／解锁／节点的操作，在副本上计算新状态，验证后写入；写成功才向 UI 发布“已获得／已进入下一节点”。
- 同目录临时文件写入与刷盘后，Windows 已有文件采用可用的原子替换并维护上一个有效备份；首文件用同目录提交。失败时保留最后有效状态并提示重试，不先删正式文件再尝试补写。
- 新模式不能走 `GameRoot.Persist()` 的无提示 `catch { }`；不做保存失败却显示奖励领取成功。[S08–S09]
- 正文损坏先验证备份；两者均无效时报告恢复选项，不默默调用 Reset 清档。
- `runId + nodeId + battleOrdinal` 构成结算身份的一部分，重复回调、重复点击、关闭重开不能重复发放。
- 首通奖励与 `resultApplied` 在同一次提交里更新；写入前崩溃只回退到旧有效状态，写入后崩溃重开识别已领取。
- 游戏中间不要求逐 tick 存档。进入战斗前持久化检查点，退出时回到同一场起点；MVP 文案明确这一点。
- 测试只能使用临时目录与测试 profile，不清理用户原档，不批量删除历史录像与素材。

### 10.3 运行入口与原存档隔离

新构建的普通启动默认进入原创入口；调试／旧版回归模式仅用于开发与历史测试。模式选择应在 `GameRoot.Awake` 读取存档之前完成，不能先加载原个人存档，再假装切到隔离模式。

现有 HUD 若依赖 `SaveData.GetUnit` 等访问，可以从新 profile 生成一个**脱离原存档的只读用途视图**供它读取；原型自动写入／加金币／换装备回调不可因此被重新暴露。用模式路由阻断老商店、抽卡、随手升级、日常、邮件等入口，不删除原代码来冒充已修复经济系统。

新胜利分支调用 `ExpeditionFlow.CompleteBattle`，不能继续进入 `SaveStore.ApplyVictory`。节点继续按钮与旧 NEXT 的章节索引逻辑分开，Boss 重试走检查点，不复用“简单重新 StartBattleAt”的旧语义。

### 10.4 临时内容与全局数据隔离

在战前由 `RunBattleFactory` 构建冻结的本场配置：角色、开局生命、基础进度、技能与效果覆盖、遗物列表、首领定义、规则开关和种子。

当前 overlay 是实例级入口，但接收对象引用；调用者不能把 `Catalog.TrySkill()` 返回的共享对象直接改值后放进去。要克隆，包括数组与嵌套可变字段。[S06]

仅当角色／敌人或关卡不能通过现有入口隔离时，增加一个可选的本场内容上下文供构造、LoadWave、ResolveSkill／Effect 使用；原调用默认行为保留。不为此写第二套结算器。

构筑效果在工厂或明确遗物钩子处生效，不能散落到每个 UI 按钮。不得每帧重建 Catalog，不能通过暂时替换全局字典再恢复来实现局内隔离。

## 11. 回放与版本：结果可追溯，不冻结设计

新模式需要把独立规则标识与原 legacy 格式区分。保留旧数值分支和旧序列化的兼容能力，不为了本模式重写或篡改历史 tape。

新回放至少绑定：

```text
modeId / rulesetId / schemaVersion / contentHash
runId / encounterId / battleOrdinal / attemptId
battleSeed / party / openingHp / openingProgress
resolved skill/effect overlays / relic IDs and parameters
boss configuration / clock policy / player commands
independent end boundary / final deterministic state / events
```

- 配置与候选是输入；FinalDigest、结算数字和预期事件只用于比较。
- 新状态比较包含：首领阶段与意图、面具实例代数、A 蓄能、C 和声／强奏状态、遗物有限触发状态。不能只比较 HP 就声称新系统完全匹配。
- 相同版本、输入配置、seed、命令必须复现。改平衡后提升 content/rules version；不同版本允许明确拒绝，不承诺所有版本互相重放。
- 旧基线真实回归要保留。若某个旧测试只针对已退出新模式的 DC 教程／流程，保留 legacy 专属测试并新增原创测试，不批量改断言为“只要不崩”。
- 若新钩子影响既有回放，先定位实际原因；不改随机种子、禁暴击或放宽误差来掩盖问题。
- Jev 以后接入时也只保存确认后的合法指令配置，回放不再次请求模型。当前不增加 API 实现或模型版本依赖。

## 12. 画面与交互要求

保持已有竖屏基线，不要求用户先定最终画风。首先解决信息层级：首领与意图区、可选目标、五人状态、主技能、局内遗物、暂停。

- 首领预警必须同时有图形与文字／进度，不只靠红色或音效；游戏暂停时读条不走。
- 遗物卡用一句话说明因果，详细倍率／上限可展开。选中前能看到与已持有核心的联系，不能满屏堆多段说明。
- 强化触发有对应图标反馈，A／B／C 的关键状态可见；显示结果来自结构化结算数据。
- 缺图使用明确占位，不联网临时生图；现有角色图必须匹配真实角色 ID，不拿首领或队长图凑。
- UI 装饰不抢输入；连续技能、暂停、退出、重试后无残留全屏层或静态单例污染。
- 不以完成原作 SHOWTIME 精确复刻作为这一版前置。角色聚焦只服务技能归因与美术可读性。
- 封面级美术、批量角色、语音和复杂动画不在本版分母。使用有分发权限的资产制作交付包；原作参考素材不自动打包进去。

## 14. 验收：功能成立与“是否好玩”分别报告

### 14.1 技术完成条件

1. 无调试参数的独立 Win64 包能完成 N0→N7→结算→返回→新一趟；产物不依赖源码路径。

### 14.2 证据与运行要求

- 接手先从本地实际 csproj、asmdef 和既有脚本确认命令。核心修改需跑已有全量核心测试和新增定点测试；UI 修改需运行实际 Unity UI 测试。

### 14.3 体验复核，不编造结论

报告三个事实：

- 在哪次选择后组合开始运转，玩家在哪场战斗真正用了它；
