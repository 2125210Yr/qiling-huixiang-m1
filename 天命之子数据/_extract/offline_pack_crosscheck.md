# 单机 dc1.1 × 数据表交叉核验

对照源：韩服私服包 `destinychild.sql`（637 名角色主数据）。
被核验：`天命之子数据/汇总表.csv`（纪念版 561）、wiki `characters.csv`、`puppets.csv`、`soul_cartas.csv`。
SQL 名字是韩文，纪念版是中文；**不能靠字符串直接相等**，所以人数/星级/职业用计数，面板用五维指纹对。

## 1. 包是什么

- 韩服 Destiny Child 单机 1.1（作者 sluteuio）。SQL 是运行时主数据，不是纪念版客户端。
- 可玩角色前缀 `101`/`102` = **496**；`201` 是杂兵/材料 **141**；合计 637。
- 纪念版图鉴是冻结的 561 人。两边**本来就不会人数相等**。

解读（看「SQL 全部」那列，不要只看 101+102）：
- 低星很多挂在前缀 `201`（材料/杂兵号），纪念版图鉴仍把它们当 1★/2★ 孩子。所以 **1★ 两边都是 50，是对齐的**。
- 2/3/4★ SQL 全部略多于纪念版（+4 / +8 / +8）。
- 5★ SQL 336 vs 纪念版 282（+54）：韩服后期五星；纪念版 282 里还有约 10 对造型重复卡。
- 前缀 101+102 的「可玩」496 **小于** 561，是因为低星被算进 201，不是纪念版多造了 65 人。
- **纪念版 561 对纪念版图鉴正确；对韩服 1.1 私服不是完整表。**

前缀 201（杂兵号）按星：{'2': 39, '3': 31, '1': 37, '4': 12, '5': 21, '6': 1}。角色 6–9：{'5': 12, '2': 32, '3': 11, '1': 28, '4': 20, '6': 25, '7': 5, '8': 5, '9': 3}。

## 4. 五维面板指纹（naked catalog vs 我们的 init）

| 对照 | 唯一命中 | 指纹撞车 | 对不上/空 |
|---|---:|---:|---:|
| 汇总表 hp_init 五维 | 0 | 0 | 561 |
| 汇总表 hp（纪念版 OCR 面板） | 0 | 0 | 561 |
| wiki characters.csv hp_init | 0 | 0 | 345 |

结论：纪念版详情页上的 HP/ATK **不是** SQL 裸体目录值（含等级/好感/装备）。
`hp_init` 若真是 1 级裸装，命中率会高；现在几乎对不上，说明我们表里的 init 多数是 OCR 当场面板，或 wiki 空着。

### 指纹命中后的属性投票（仅供参考）
命中太少，**不能**从这一步锁定 attribute 1–5 对应哪一系。

### 职业投票（应与预设 1攻2防3扰4治5辅 一致）
无。

## 7. 模式目录（SQL 有、我们动效页缺录像）

- 主线/困难：`game_area_dungeon` **304** 条，30 个 area。先前分析 `area_type` 1 和 2 各 152 = **普通 / 困难** 两套。
- 星云：`game_spacewalk_area_dungeon` **256**，changelog 说一千多关；stage_mob 2048。
- Raid：`special_raid_dungeon` **67**（yaml `raid: 49`，注释 0–56）。
- 世界王：`world_boss_serial_mob` **74**（yaml `world: 27`，1–38）。
- 这些是**关卡目录**，没有每关美术、也没有打击公式。动效页缺主线/困难/星云录像，SQL 补不上画面，只证明模式存在且可切。

## 8. SQL 有、我们数值页没有的

- 每名角色 5 个技能 **ID**（AUTO/TAP/SLIDE/DRIVE/LEADER），没有伤害数字。
- 装备 2952 + 词缀 4406 + 强化/突破表。
- 点火 6 节点 × 488 人 = 2928，以及点火石树 3072。
- 温泉好感百分表 `character_spa_status_percent` 240 行。
- `skill_effect_path` 7257 是特效路径，5477 条是 `none`，**不是**公式。

## 9. 总判

| 项目 | 判 |
|---|---|
| 纪念版 561 人数 | **对纪念版图鉴是对的**；对韩服私服 **不是完整表** |
| 1★ 50 | 与 SQL **全部** 1★ 一致（多数 201 号） |
| 5★ 282 | 少于 SQL 全部五星 336，缺韩服后期 |
| 魂卡 156 | option 唯一 322 ≈ 156×2 普/闪 + 约 10 张后期 |
| 职业/属性空 | 表缺，不是 SQL 缺 |
| 面板数字 | 与 SQL 裸体目录 **对不上**（OCR/装备后数字） |
| wiki_name 错位 | **表错**，约从 M5-002 起串行 |
| 人偶 220 | 少于 SQL 253 |
| 魂卡 156 | 需看 option 唯一 item；特效来自 wiki 不是 SQL |
| 伤害公式 | SQL **没有**；继续用 GameKee 实测 |
| 主线/困难/星云 | SQL 证明两套 area_type + 星云 2048 关；无画面 |

不要把私服韩文名、技能 ID、裸体面板写进发行客户端。核验只用来标我们表哪里空、哪里串行。

## 10. locale.pck 字符串（只计数）

韩文词条 20470 个，中文词条 81058 个。PCK 头是自定义 `PCK\0`，不是 zip。
若要用它做韩↔中对照，需要另写解包；这次核验 **没用原文名字去改表**。
