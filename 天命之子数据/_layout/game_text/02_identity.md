## 2. 现有身份长什么样

CSV 身份列：`id, idx, name, name_ocr, wiki_name, wiki_id, rarity, element, role, cv`。

没有独立列：称号/epithet、本名、绰号、简介、召唤台词、家园待机、检视 flavor。称号被焊在 `name` / `wiki_name` 字符串里。

### 展示名 `name`

纪念版 OCR → wiki 正式名已经跑过一轮（`11_notes.md`：改名 108 / 已是正式名 442 / 拒绝猜 11；CSV 实际 `name` 更新 104 行、`wiki_name` 更新 66 行）。

展示名来源分层：

1. **韩 wiki 译名整串**（多数 5★）：`黑暗塞勒涅`、`哀悲的索卡`、`将成神的马尔杜克`、`优柔寡断的菲罗忒斯`。称号+本名不可拆。
2. **局内短名**（纪念屏只印了本名）：`泽卡提`、`石见`、`希妮`、`塞列欧斯`、`诺特斯`、`都桂花`、`赫克特`、`摩亚`、`米里娜`、`迪娜希`、`荷米斯`。对应 `wiki_name` 才是完整称号串。
3. **日服 dcj 顿号正式名**：`光巴里、服从边界`（`11_garbled_list.md` 明确不当乱码）。
4. **联动/拉丁**：`SNOW MIKU`、`Super 珂丝敏`、`薮猫（限定）`。

## 5. GameKee 韩式头衔 vs 局内短名

国际服 wiki 从韩服图鉴搬「修饰语+神话名」，再逐字译成中文。局内（纪念版字条、编队条）经常只显示神话名或短称号。

后果：

- 同一人三套字符串：`name_ocr`（脏/短） / `name`（展示，有时短有时全） / `wiki_name`（韩式全称）。
- 不能用「wiki 全称」当编队名：`抵抗的泽卡提` 太长；也不能只用短名当图鉴标题（重名：两个北国俱毗罗、两个希妮、两个神枪手希尔德）。
- 皮肤/属性变体共用短名，靠 `id` + `element` 区分；wiki 一篇对多行 CSV（`大力无双哈索尔` M5-010/011）。
- 词条定位写「辅助」，CSV 写「辅助型」—— UI 要统一一种。

推荐身份模型（尚未建表）：

```
id | given_name | title | display_full | display_short | wiki_name | nickname | cv
```

`display_full` ← wiki 韩式全称；`display_short` ← 局内短名；`title` ← 从全称拆出的修饰语。现在全焊在一个 `name` 里。

## 6. 完整游戏还缺的身份文本

CSV / GameKee 天子页 **都没有** 下列字段。详情 dock（`12_notes.md`）只用 `name` + 稀有度/属性/定位 + 技能，且禁止塞 wiki 名。

| 文本 | 现状 | 完整游戏用途 |
|---|---|---|
| **角色简介 / bio** | 0。wiki 无简介栏 | 图鉴详情、检视 |
| **称号 / titles** | 焊在名字里，不能单显 | 名牌上「称号 / 本名」两行 |
| **绰号 / nicknames** | 仅绰号表截图，未结构化 | 图鉴检索、社区名 |
| **召唤台词 / summon quotes** | 0 | 抽卡、获得演出 |
| **家园待机 / home idle lines** | 0 | 家园/客厅 |
| **检视 flavor / inspect** | 0（技能描述不是 flavor） | 长按立绘 |
| **稀有度显示串** | 仅 `N星` 五档 | 需 `★★★★★` / 图标 / 多语言 |
| **定位显示串** | 293/561 有 `X型`；wiki 无「型」 | 编队、筛选、详情 badge |
| **属性显示串** | 507/561 有单字；54 空 | 同左；空的多为重复皮/史莱姆 |

连带缺口（身份相邻）：

- CV 439 条需人工校对；122 空（低星为主）。
- 5★ wiki_name 仍空 7；role 空 87；element 空 38。
- 皮肤官方名（必胜的哈索尔等）只在 wiki HTML 尾巴，未进 CSV。
- 客户端 `catalog.json` 只有 25 个可玩短名（冰刃、潮汐祭司…），与 561 图鉴不是同一套命名。

数据源优先级（尚未做）：日服 dcj 词条 / 韩服原文称号 / 纪念版字条短名 / 国际服 GameKee 汉译。国际服汉译不能当局内唯一真名。
