## 2. 技能文本语法

两套并存，同一张表里混排。

### 2.1 电报体（后期国服 wiki 拆条）

`效果名：时长内，目标 数值`

```
对目标造成401（2588）伤害1次觉醒：15秒内，1名水属性攻击型70（90.1）%几率
```

点火 U 常把 **秒 → 回合**，并丢掉 MIN：

```
对目标造成2613伤害1次 觉醒：2回合内，1名水属性攻击型95.1%几率
```

常见块：`造成N伤害K次` + `效果名：` + 时长 + 目标过滤器 + `±N%` / `±N` + `概率|几率|机率`。

### 2.2 散文体（较早词条 / 玩家整理）

```
对随机2名敌人造成735（4035）伤害，赋予5名火属性盟友（最高攻击力）Skill伤害+50%（115%），持续16秒，有75%（90.2%）的几率赋予所有流血的盟友净化（将流血转为持续回复）
```

括号里夹效果规则：`屏障（在HP受影响前，吸收…无法与减益屏障同时启用）`。

### 2.3 动词

| 类 | 用词 |
|---|---|
| 伤害 | 造成、优先造成、连击、加成伤害、无视防御伤害、魔力伤害、伤害共振 |
| 赋予 | 赋予、获得、套用、永远套用 |
| 移除 | 移除、无效、无效化、净化、充满、结束冷却、重设/重置量表 |
| 治疗 | 回复、持续回复、治愈、复活、重生、紧急输血 |
| 控制 | 造成中毒/流血/晕眩/诱惑/沉默/石化/冰冻/睡眠 |

### 2.4 目标

- 数量：1–5 名、全体、随机、前排、后排、自身  
- 阵营：敌人 / 盟友 / 队友 / 友军（用词不统一）  
- 属性：火/水/木/光/暗 +「属性」  
- 职业：攻击型、防御型、干扰型、治疗型、辅助型  
- 选择：最低/最高 HP、低/高攻击力、最低攻击力、受减益、有增益、充能中、死亡、魅惑中、流血中  
- 优先写法：`（优先：最低HP）` / `最低HP优先` / `优先造成`

### 2.5 时长

| 单位 | 典型值 |
|---|---|
| 秒 | 4 / 5 / 8 / 10 / 12 / 14 / 16 / 20 / 24；队长技偶发 `500秒内1次` |
| 回合 | 2 / 3 / 4；点火后秒→回合 |
| 次数 | `20秒内3次`、`14秒内1次`（忍耐/减益无效层数） |
| 永久 | `永远套用`（队长技） |

### 2.6 数值形态（等级缩放占位）

| 形态 | 含义 |
|---|---|
| `102（691）` | MIN（MAX），技能 1 级 vs 满级 |
| `50（115）%` | 百分比 MIN（MAX） |
| `449（105%）（3399（155.6%））` | 固伤 + 百分比刀双写 |
| `605（130%）【4214（177.2%）】` | 同上，括号风格乱 |
| 点火列只留 MAX/U | `造成2613伤害`，无 MIN |
| `造成X伤害` / `回复XHP` / `+X%` | **未填的点火或满级**，24 行含此占位 |
| `Y额外伤害` | 更残的第二占位（如 M5-265） |

**没有** `{0}` / `%d` / `$VALUE` 一类程序占位符。要做可缩放 HUD，必须从 `MIN（MAX）` 对自己解析，或另建数值表。

## 6. 完整游戏仍然缺少的清单

要「可玩 + 可展示」的技能文本，不是 561×8 格子填满就够。缺项按优先级：

1. **独立技能名**  
   Wiki / 汇总表都没有。只有槽位（普攻/TS/SS/DS/队长）。韩/日原作每人技能有专名；国服图鉴页也常只写槽位。  
   现有干净 HUD 名只在 `client/Assets/Content/catalog.json` 的 25 名原创角色（刃息/直斩/裂空…），**不能**回填纪念版 561。

2. **短 HUD 名**  
   战斗条放不下 80–200 字正文。需要 2–6 字按钮名（可与专名同一套）。现在详情页用「TS/SS/DS」缩写凑合。

3. **3★/2★/1★ 全套技能**  
   202 人。wiki 无页。纪念 OCR 只有 5 条垃圾。要嘛从日/韩 wiki 或客户端包拆，要嘛为低星写通用模板（史莱姆/龙/注射器族可共用）。

4. **5★ 81 + 4★ 20 的缺页套件**  
   对齐 `wiki_id` / 韩服 `destinychild` / 日服 `dcj` 补正文。皮肤重复行（哈索尔·光、妲比·水）应引用本体技能，不要空着。

5. **点火 U 全文**  
   有套件者缺 258−166=**92** 人的三槽 U；4★ 只 9 人有 U。队长技/普攻本来就没有 U，不要强行造。

6. **等级缩放数据，而不是嵌在句子里的 MIN（MAX）**  
   要程序化：`flat_min/flat_max`、`pct_min/pct_max`、时长、概率、目标数。`skills.csv` 已拆 `dmg_min/dmg_max/dmg_ignited`，但只覆盖主伤害，不管 buff 幅度。`造成X伤害` 必须回填数字。

7. **效果 ID 而不是纯中文**  
   93 条 buff 表不够。狂暴/攻击态势/时间扭曲等要进效果表，否则战斗不能结算。公式层已区分「最终伤害 %」vs「Skill 伤害 %」vs 固伤（`wiki_ts_ss_ft.txt` EX2）。

8. **模式闸门枚举**  
   统一 `pvp` / `raid_5` / `wb_20` / `world_boss` / `dungeon` / `fever` / `labyrinth`。现在同一闸门至少 6 种写法。
