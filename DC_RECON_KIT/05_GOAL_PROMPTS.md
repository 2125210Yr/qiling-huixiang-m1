# 可复制的 /goal 工单
资料依据：[S28][S29]，研究日期 2026-09-09。官方 Goals 示例要求 Codex 0.128.0 或更新；实际先 `codex --version` 并检查是否支持 `/goal`。不要自动升级或覆盖配置。

## 1. 本地配置核对
将模板目录中的片段合并到当前项目 `.codex/config.toml`，不要重复表或覆盖现有安全配置：
```toml
[agents]
enabled = true
max_concurrent_threads_per_session = 4
```
需要自定义角色时，把 `codex_templates/agents/` 中 TOML 复制到项目 `.codex/agents/`；模型和推理档默认继承父会话，不强制换模型。版本不支持时，使用当前真实支持的 spawn 能力传入同样角色工单，不伪造“已启用”。

`/goal` 负责目标持续推进，不等于自动开多个子代理；下文显式要求 spawn。权限/工具/资料不足时，目标仍可能阻塞。用 `/goal` 查看，`/goal pause` 暂停，`/goal resume` 继续；具体以本地帮助为准。[S28]

## 2. 第一条启动命令（整个代码块复制到 Codex）
```text
/goal 在当前既有 Unity 项目内执行 DC_RECON_KIT 的 M1：先完成 G0 工程审计和 G1 目标/契约冻结，再做 G2 高还原核心战斗切片。首先完整阅读现有 AGENTS.md、DC_RECON_KIT/00_README.md、01_RESEARCH_AND_SPEC.md、02_NUMERICS_AND_CALIBRATION.md、03_MULTIAGENT_AND_MILESTONES.md、04_ACCEPTANCE_AND_TESTS.md、sources.json 和本文件的“主协调者执行合同”。明确 spawn 只读 dc_research、dc_audit 与 dc_qa，收齐结论后冻结接口，再按依赖派发 dc_math、dc_battle、dc_ui、dc_presentation，同时最多 4 个子代理。优先修复并复用现有框架，不另起通用卡牌项目，不自行升级 Unity 或覆盖用户未提交改动。不要把角色立绘、具体角色技能和文本创作算成你要替用户完成的内容，但必须实现通用技能执行器。目标服未明确时先做不依赖服别的审计，不得混用 KR/JP/GL 数值。按合同交付实际可运行、可录制、可对照的核心战斗切片与真实测试证据；任何关键参考或环境缺失标 BLOCKED，不得伪称达到90%。M1 验收后停止扩大范围，提交下一阶段入口。
```

## 3. 主协调者执行合同（必须读取，不是可选建议）
你是集成负责人，不是只写方案的顾问。请实际检查文件、修改获授权范围内的代码、运行可用工具并交付证据。不存在工具时必须报告，不可编造执行。

### 输入边界
用户已有 Unity 框架；原生骨骼可暂用，Live2D 未定。用户负责角色插图、具体技能表及文本。不要把旧 AI 的设计文档当原作证据。之前的临时伤害公式、成长曲线等只有有来源才可晋升为规则。

### 开始时
1. 定位 ProjectSettings/ProjectVersion.txt、Packages、入口场景、项目既有规则与测试；记录 Git 状态，保护未提交数据。
2. 取得真实编译/启动基线，工具受限则记录静态审计结果和限制。映射现有脚本调用链，分类 REUSE/REPAIR/ISOLATE/REPLACE，所有结论附路径/符号/证据。
3. 收集目标服务区、日期、画幅、模式、可用录屏/截图/数据。用户尚未确认时一次性提出最小必要问题，同时继续独立的只读工作；不可自己选服后声称还原用户记忆版本。
4. 不访问用户账户敏感数据；本地资料只读采集。若使用设备连接，明确会操作哪些界面；完成已授权采集后停止输入并告知用户可以断开连接，不改变或导出账户凭证。

### 研究与验收先行
每条规则绑定 sources.json 中对应来源或新增已实际阅读的来源。补齐 region/date/conditions；跨服或跨年份必须解释迁移理由。未证实项进入 UNKNOWN_REGISTER。链接存在不代表读过文章，标题“源码”不代表代码已核验。

每个关键状态先有参考、红测试、通过条件。不能只抽“漂亮图”而不保留点按、滑动、就绪、QTE、Fever、受控/死亡、结算过程。营销图不能当原生屏幕的精确坐标。

### 子代理工作
先 A 波三个只读角色，再建立契约、文件租约与集成分支。允许最多四个并发子代理，禁止子代理继续无限生成代理。每个角色必须知道输入、所有权、依赖、测试与交接格式。主代理负责冲突，不让两个代理各自生成一套 CombatContext 或角色数据模型。

现有共享 `.unity/.prefab/.meta`、Packages 与活动 Unity 编辑器只允许主代理写入。代码写入独立边界；新增资产须明确 GUID/所有权。只能在审计后分配真实目录，不能按本包的建议名字创建第二套平行系统。

### 核心切片的功能
保留五人可观察战斗：自动基础攻击、Tap、Slide、充能/CD、目标选择、buff/控制、Drive 选择与 QTE、Fever、死亡/换波、胜负与结算、手动/自动/速度。底层编队不硬编码所有模式都是五人。角色仅用合成 fixture 或用户已有合法素材。

模拟、UI、动画、VFX、音效分离。不得依赖动画结束触发逻辑伤害，不把所有时间进度共用一个冷却，不把毒统一实现成每秒 DoT，不拿 GenericDamage=ATK*倍率-DEF 做终版。历史参照器只用于它声明的条件；GL 最终规则缺失就保留未知。

UI/表现必须随逻辑集成，逐帧对照，不接受“功能先完成后面再重做外观”。角色适配器能保持当前骨骼方案，先做一角色对照，再讨论是否切 Cubism，不能无证据全面迁移。

### 每轮实际验证
先做纯逻辑测试，再当前 Unity 工程的 EditMode/PlayMode、入口流程和录屏对比。使用现有可用自动化桥；无桥时先确认最小兼容接入，不未经批准更改工具链。测试任务发出不等于通过，必须读取结果和日志。不得生成伪造“原版参考帧”。

固定 seed 和输入日志可回放。显示版别与 dev/profile 信息只在开发调试层，不污染正式目标 UI。所有未知占位有明确标识，不偷偷通过审核。

### 停止与失败行为
同一缺陷最多连续三轮无进展尝试，之后提供诊断、冲突证据和最小下一步；不无限搜索、不无限重写。外部材料缺失时整理准确缺件清单。关键未知不能用临时参数关闭目标。

M1 只有在验收合同允许的范围内才算完成。交付状态 COMPLETE / BLOCKED / NEEDS_REFERENCE，并列：实际改动路径、基线与当前差异、测试原始路径、录屏/截图、数值误差、范围/证据覆盖率、未知清单、剩余风险。没有用户原项目就绝不能声称已审计。M1 完成后不自动进入全游戏扩展。

## 4. 后续目标（各自验收后再使用）
### M2：成长闭环
```text
/goal 在已验收的 M1 上执行 DC_RECON_KIT 的 G3/M2。先读取上次结果、TARGET、契约和 UNKNOWN_REGISTER，保护已通过的战斗与视觉回归。spawn dc_meta、dc_ui、dc_math、dc_qa，按依赖执行关卡→编队→战斗→结算→奖励→养成/装备→再次战斗及原子存档/中断恢复。用户提供的技能/角色表通过校验导入，不编造缺失原版值，不新建真实支付/账号后端。主代理独占共享 Unity 资产。交付可玩的闭环、真实回归证据与未实现范围；通过后停止扩展。
```
### M3：模式差异
```text
/goal 执行 DC_RECON_KIT 的 G4/M3，按冻结的目标服玩法优先级逐个补齐模式。先对每模式制作原作证据与规则差异表，再复用已有 BattleCore。特别要求 World Boss 的20人前后排、自动行为与Drive顺序成为实际逻辑；Ragna/Underground/Narrative/Rumble/Rebirth/Endless Duel 按目标版证据落地，不用高HP敌人或空菜单冒充。最多四个子代理按依赖轮换，每模式独立测试、截图/录屏和结算证据。离线模拟服务明确标示，不宣称存在真实联网协作和排行。
```
### M4：后期系统与最终验收
```text
/goal 执行 DC_RECON_KIT 的 G5/M4。补齐目标版 Soul Carta、Ignition/增幅、装备选项及已冻结的后期循环，保持角色内容由用户提供。校准代理与独立QA复查最终版本来源、数值误差和关键表现。报告完整约定范围的覆盖率、证据覆盖率及领域分数；未实现/未知不得从分母删除。完成目标设备构建与性能测试；无真机则明确阻塞真机验收。不得自动发布原作资产或游戏。只有关键验收全部通过且约定范围达到门槛才宣告目标完成。
```
