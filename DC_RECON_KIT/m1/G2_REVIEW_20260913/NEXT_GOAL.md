## 4. 必须落实的修复

### A. 分开两种测试

保留 VerticalSliceSmokeRuntime，但明确为状态展示/演出冒烟，可以使用显式夹具注入。它不能单独通过自然流程验收。

新增实际界面输入 E2E：从普通入口进入，操作编队/关卡、Tap、上滑、Drive/QTE、Fever、暂停/倍速/自动、结算和返回/再战。通过真正的 UI 输入事件或设备指针操作走同一手势链，不能把 GameRoot.Go/Tap/FireDrivePerfect 等直接函数调用当作实际按钮测试。

初始测试关/阵容可使用固定且对玩家可见的合成数据；正式开始后不能改充能、HP、Drive、剩余时间、胜负状态或强制清场。不能以隐藏的 QA 特供无限生命/充能配置冒充普通运行入口。

必经步骤缺失应失败，不跳过继续整体 PASS。对新流程分别记录预期状态、实际状态和证据。

### B. Fever

手动模式通过实际输入提交 Fever 命令；自动模式通过受配置控制的自动策略提交同种命令。点击角色与出手角色有可测关系，不恒定 FirstAlive。

窗口、预算、输入节流和结束条件分别定义，修复默认参数导致的实际窗口与声明窗口冲突。原作具体数值保持延期/待验证；本批工程预览政策明确标为设计值。

结算使用角色/技能数据可配置的 Fever 分支和通道政策，而不是把“独立 opcode”误解为“永久独立于角色数据”。不要未经依据宣布某种特殊原作分支已验证。

### C. QTE 与末态

核心唯一拥有 QTE elapsed/remaining、判定状态与结束事件；HUD 仅展示和提交输入。移除界面与核心各自决定超时的竞争关系。

QTE、关卡倒计时、暂停、倍速和展示时钟按显式政策分别运行。覆盖速度1/2/3以及不同时钟缩放配置。

终局、被取消或已失效的 QTE 回调必须无结算副作用；ResolveDrive 的返回结果被界面正确处理；不得在失败后的迟到回调里追加伤害、Fever 或奖励。

### D. 随机与输入可复现

同 seed + 同初始数据 + 同 tick 命令序列应得到可重复结果，但正常工程预览不关闭全部暴击。ForceNoCrit 仅用于显式公式夹具。

玩家手势、自动策略和回放走统一命令入口。日志至少包含输入序号/tick、类型、角色槽、接受或拒绝原因、seed、数据/规则版本和运行模式。比较事件记录与最终战斗状态，不只看一个哈希字符串。

### E. 效果能力与生命周期

能力登记不得只检查 opcode 已知，还要检查 effect kind 与参数是否真实受支持。Silence/ChargeSpeed 等不能挂上状态却没有作用；未实现时在内容校验阶段明确报错。

补齐本切片实际使用的状态到期、替换、堆叠上限及副作用清理。护盾数值与其来源/寿命要有明确政策；驱散与到期分支分别可测。

毒、流血、周期伤害分开配置触发政策，不凭旧错误合并写死。没有证据的原作政策仍未验证。

不要求本批一次性实现全量穿防、反射、复活等，但必须准确列出实现面；抛错防护测试通过不能算技能已经可用。

### F. 计算与证据分离

不把“能计算”与“原作已实测”合为 Measured 一个状态。允许工程预览用设计值/历史候选跑完，但每个分支保持准确证据标签。

保留严格 GL_UNKNOWN 验证路径拒绝伪真值。不要把普通预览入口简单切为全部无伤害，也不要偷偷把 JP 改名为 GL。

实际 Drive 未验证分支不得仅因为返回数字而成为经验公式真值。对 KR Slide 历史附加衰减、穿防有效域等，按已有参照器声明的输入范围和分支补交叉测试；这不是重新启动最终 GL 数值调研。

### G. UI 与展示

UI 随上述行为同步修复：没有输入不显示命中；QTE 结束不遗留交互层；暂停、换波、结算状态不互相遮挡或误触；重复进入退出不积累资源。

使用已入库 P0/P1 做可辨的结构检查，不开展已暂停的外部搜片。T27/T28仍延期，本批不输出像素或逐帧还原通过。

等级/突破循环修改和胜利后固定 LEVEL UP 保持开发占位身份，不算养成闭环。不因修显示而进入 M2 经济系统建设。
