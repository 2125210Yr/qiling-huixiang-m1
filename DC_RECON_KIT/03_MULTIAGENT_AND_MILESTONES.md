# 多子代理编排、目录所有权与里程碑
## 1. 一个主协调者，八个可轮换专业角色
同时最多 4 个子代理，不包括主协调者。token 充足优先投入独立验证和对照实验，不是重复让很多代理写同一模块。当前 Codex 自定义代理格式见 [S29]，模板不能无检查地覆盖本地配置。

| 角色 | 责任 | 交付证据 | 写入边界 |
|---|---|---|---|
| dc_research | 官方/原始实验、版别和矛盾整理 | 带来源、日期、条件的事实清单 | 默认只读，交主代理落盘 |
| dc_audit | 当前 Unity 调用链、复用/修补/替换决策 | 真实路径、日志、依赖图 | 只读 |
| dc_math | 数值候选、校准与舍入/分支测试 | 参数域、测试、误差报告 | 获租约后的数值/测试目录 |
| dc_battle | 时钟、状态、目标、效果、回放 | EditMode/PlayMode 证据 | 独占战斗代码边界 |
| dc_ui | 参考测量、布局、手势、UI 状态 | 对照截图、热区与几何报告 | UI C#；共享 Prefab 由主代理集成 |
| dc_presentation | 动效、VFX、音频、角色适配 | cue sheet 与逐帧比较 | 独占表现代码/新资源；不动共享场景 |
| dc_meta | 数据导入、养成、背包、奖励和存档 | 事务/迁移/中断恢复测试 | 独占 Meta/Data/Save 边界 |
| dc_qa | 独立验收、边界测试与性能 | 原始结果、复现、截图/录屏 | 测试/报告租约；不偷偷修生产代码 |

主代理持有接口契约、integration 分支、现有 `.unity/.prefab/.meta` 和包清单写权。自定义 agent 名不代表有了权限；沙箱与用户批准仍须遵守。

## 2. 波次安排
A：research + audit + qa 三个只读任务并行。确认版别、能否运行、原项目最大不还原点。
B：主代理冻结数值/事件/数据/表现接口；所有人先读契约。
C：battle + math + ui + presentation 四个独立边界并行，至少每天/每工作批次做一次集成回归。
D：释放完成角色的线程，meta 入场；qa 持续独立审查，对比原始证据。
E：主代理统一集成与 Unity 录制，qa 最终签验。写代码的代理不能单独给自己打“90 分”。

不得子代理再无限 spawning。任务阻塞时返回依赖和最小所需证据，不在同一失败方向反复制造代码。

## 3. Unity 协作规则
代码代理可使用独立 worktree；每个 worktree 不共享 Library 缓存目录。不能假设多个 Unity 编辑器可同时低成本运行。

活动集成编辑器只有一个写入者。所有 MCP 场景/资产命令确认正确项目与实例；未分配资产租约时，不得编辑、重命名、复制或重建共享 Prefab/Scene，也不得随意更换 GUID。新增资产的 `.meta` 必须一起管理。

先保护用户未提交改动；禁止 reset --hard、清理未跟踪文件或覆盖用户存档。不得把临时日志里的密钥/账户资料提交仓库。

每项任务包含：task ID、父里程碑、依赖、依据/版别、允许路径、禁止路径、输入输出契约、验收命令、样本 ID、失败行为、交接格式。每个代理返回事实而非“已经优化得很高级”。

## 4. 完整路线图与闸门
### G0：基线审计与目标冻结
输出 AUDIT.md、TARGET.json、REFERENCE_INDEX.json、UNKNOWN_REGISTER.json、BASELINE_LOGS。
通过：能明确说明现有工程哪些可复用、哪些导致不像；有来源可靠的目标参考。无法运行时报告真实阻塞，允许只读审计继续，不声称运行通过。

### G1：规则与界面契约
输出 CombatContract、EffectSchema、ClockPolicy、FormulaProfiles、UI 状态地图、至少一组目标版原生界面/战斗参考。
通过：Tap/Slide/Drive/Fever 等已拆开；角色内容可外部填入；没有全局默认原版公式；未知量有显式缺失处理。

### G2 / M1：高还原核心战斗切片
一组五人测试阵容，一场短战斗，包含自动攻击、点击、上滑、Drive/QTE、Fever、控制/护盾/目标切换、死亡/结算、暂停/加速/自动操作；具体切片状态以参考录像为准。
表现必须同时做，不接受“先丑着，后面一键换皮”。包含基础入口和返回，以便从真实客户端流程进入。
通过：全部关键状态测试；对照视频；角色美术可替换；数值未知必须显式说明。无法取得参考的精确数值分支不得以临时值获得 fidelity pass。

### G3 / M2：可玩的成长循环
关卡 → 编队 → 战斗 → 结算 → 奖励入账 → 等级/进化/突破/装备等 → 再入场。用户提供真实角色/技能数据后替换合成测试数据。
通过：消耗与奖励幂等、存档恢复、主界面/详情/编队/结算 UI 对照通过；流程状态没有只做截图不接逻辑的空壳。

### G4 / M3：模式差异覆盖
先目标优先级最高的 Ragna / World Boss，再日常、Underground、Narrative、Rumble、Rebirth、Endless Duel 等目标确有内容。
通过：每模式独立规则/数据/测试；World Boss 真正承载 20 人前后排和自动/Drive 策略，不是五人系统摆二十张图。
离线网络替代明确标注模拟；不能将不存在的真实协作和排行榜算还原。

### G5 / M4：后期养成、边界与全量验收
核对 Soul Carta、Ignition/增幅属性、装备选项等目标期系统；完成召唤、任务、活动日历、收藏、声音、性能和打包。
通过：范围覆盖率与还原度分别达成约定门槛，未验证关键数值不计通过。全部用户素材不能作为可公开再分发包自动发布。

## 5. 第一个 14 天只验证核心切片
这是执行时间盒，不保证 14 天完成全游戏。
- 第 1 天：保护工程、实际运行、确认目标版，列最严重的 10 个差异。
- 第 2–3 天：参考与契约、时钟/输入/公式红测试、骨骼适配边界。
- 第 4–7 天：五人核心战斗与 UI 同时落地，日末/批次末录制对照。
- 第 8–10 天：Drive、Fever、受控/死亡/换波、声音与关键动效。
- 第 11–14 天：小闭环、存档、自动/速度差异、独立 QA、保留/替换决策。

加码条件：用户裸看切片已能认出 DC，关键行为证据通过，数值误差与未知项减少。暂停扩展条件：同一核心行为连续 3 轮无改善、源素材不足以测量、合并持续破坏运行，或把大部分时间花在新增菜单而核心战斗没变像。此时定位并修复阻塞，不换项目也不无限重写。
