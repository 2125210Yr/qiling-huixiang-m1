# 历史数值候选、已知差异与校准办法
研究日期 2026-09-09。以下不是“DC 全服最终官方公式”。原始实验亦包含敌防御反推、样本量和后续改版限制。[S05–S16]

## A. 证据类型与版本隔离
OFFICIAL：官方明确的规则/表值；EMPIRICAL：原始测试支持且标出条件；REPORTED：转述其他实验但未独立核对；HYPOTHESIS：解释模型；DESIGN：我们自己的临时实现；UNKNOWN：缺证据。

数据表必须带 `region, version_window, source_ids, evidence_class, conditions, overrides, superseded_by`。切换版本不是全局换一个倍率。当前可构建 `JP_LEGACY_EMPIRICAL` 和 `KR_LEGACY_REPORTED` 两个研究 profile；不得创建一个偷偷继承 JP 的 `GL_FINAL_VERIFIED`。

## B. 变量定义
`S`：当前状态解析出的技能显示伤害，**不是总 ATK，不是技能倍率**。
`Ae`：相应公式定义的装备攻击增量；某类增益是否归入该项必须独立验证。
`D`：目标有效防御；涉及百分比/固定减防的顺序仍由版本政策决定。
`Gn` / `Ge`：无装备敏捷与装备敏捷增量。
`E`：普通历史分支属性因子 0.7 / 1 / 1.4。
`c`：无额外暴伤增益的普通分支，未暴击 0、暴击 1。

S 已包含哪些角色固有成长必须由数据解析器明确。不能先使用解析完的 S，再把全部攻击力又乘一次。

## C. 可以落到参照器的公式
### 1. 普通 Tap / Normal 基底 [S05][S07]
```text
JP 候选 Btap = (400*S + 125*Ae)/(400 + 0.15*D) * (E+c)
KR 转述候选 Btap_KR = Btap * max(0.6, 1 - 0.00008*D)
```
这里的 c 是为了忠实表达原实验的算例：优势且暴击为 2.4 倍，不是 1.4×2=2.8。原文前置说明中的“暴击补正 1/2”和加号写法存在歧义，应保留该歧义记录，不把原文机械复制进代码。此式不涵盖所有特殊 Normal 类型、暴伤增益、额外伤害或最终减伤。

### 2. 普通 Slide 区间 [S06][S07]
```text
Bslide(r) = (400*S + 120*Ae + 40*r)/(400 + 0.2*D) * (E+c)
r 在 [-Gn, +Ge] 范围内
KR 转述候选另乘 max(0.7, 1 - 0.00005*D)
```
原始实验重点支持上下界；**没有证明 r 均匀分布**，且作者承认属性/暴击未全部另外检验。因此参照器只返回区间，不给一个看似真实的随机抽样器。不要换成通用 95%–105% 随机浮动。部分“普通技能连打型 Slide”不是该分支。

### 3. 防御无视通道历史拟合 [S08]
```text
P_eff = P_nominal * (0.6 + 0.4*D/20000)
```
限原实验讨论的 0–20000 防御范围；它说明某类穿防的有效值与目标防御相关，不能直接等同于全额固定真伤。系数是玩家近似拟合，不是源码精度证明。参照器遇到超范围拒绝外推；更高防御需要补实验。

### 4. Fever 分通道处理 [S09][S10]
普通分支在目标最终减伤之前：
```text
Bfever = 0.6*Btap + 0.6*P_eff + ExtraFlat
```
基本攻击连打型存在基底不按同样 0.6 衰减的例外。默认 Fever 暴击与允许暴击的特殊效果也应分开。ExtraFlat 不跟随上述普通属性/暴击/0.6 通道，不代表它无视所有目标最终减伤。防护、反射及特殊放大另按已验证顺序结算。

### 5. 自动基础攻击，仅提供候选结构 [S05][S07]
```text
Bauto = [20*A_total*E/(0.4*D+500) + S_auto - 20*A_naked/500]
        * max(0.6, 1 - 0.00005*D)
```
此处作者的敌人防御含反推假定，PvP 实测曾出现差异。不要把该项与 Tap 合并，也不要把普通 Tap 的 E+c 直接套到特殊连打型自动基底。

### 6. Drive 显示预测值，不是对敌伤害 [S16]
```text
PredictedDriveUI = S_drive + (1 + 0.2*星级)*(0.35*Ae + 0.10*Ge + 0.10*Ce)
```
它不能回答目标防御、QTE、增幅属性和模式减伤如何影响实际 Drive。必须有单独的实际伤害政策与实测夹具；不得拿预测显示值替代战斗结算。本包 Python 故意没有提供“实际 Drive”伪公式。

## D. 充能不等于 CD [S11][S14]
历史 JP 实验中不同职业有不同基础充能时间；这些只是待目标版录屏复核的初始线索，不能硬编码全服。充能速度增加 b 的候选关系是：
```text
T_new = T_base / (1+b)
```
直接增加充能 p 是对当前进度的离散改变（是否允许在 CD 中生效、溢出如何处理必须按目标版验证）；不是永久缩短冷却。充能量类增益还可能影响行动/受击触发的充能来源，单列政策。

## E. 暂不能声称已取得准确式子的项目
| 项目 | 当前边界 | 接下来用什么证据 |
|---|---|---|
| 最终服实际 Drive 结算 | 预测 UI 值不是它 | 已知装备/敌方数值的 QTE 对照样本 |
| Crit 属性 → 概率 | 旧实测不足以给精确曲线 [S12] | 足量独立就绪事件、buff/模式控制、置信区间 |
| 命中/抵抗/控制概率 | 旧文有更正 [S13] | 最新目标服公告、受控实验与事件样本 |
| 普通与增幅属性组合 | 后期 Ignition 另成体系 [S21][S23][S24] | 单独改变增幅 ATK/DEF/AGI/CRIT 的样本 |
| 整数舍入与结算顺序 | 差 1 不能一律当四舍五入 | 取整边界、逐段伤害、护盾临界点 |
| 目标 Boss 精确 DEF/模式减伤 | 视频伤害通常不足以同时求两者 | 有输入真值的友谊赛/资料/可核验表 |
| buff 叠加、快照/实时 | 不能凭名称判断 | 单 buff 与双 buff 的顺序交换实验 |
| 各服各期经验/掉率/消耗 | 本次没有取得完整定版数据表 | 用户资料、可核验公开表和对应公告 |

## F. 真正可用的数值校准实验室
建立一个可配置攻击方、目标方、装备、技能分支、属性、buff、随机种子、模式和速度的独立测试场景。它用于执行候选和比较证据，不是假装原版游戏仍可实时访问。

每条原版证据记录：服务区/日期、录像原件哈希、时间戳/帧率、攻防双方已知输入、未知量、技能显示值、是否暴击/弱点/增益、逐段输出。缺敌方防御的样本可用于定性比较，不能当完整输入真值。

### 拟合顺序
1. 先普通无增益、无克制、非暴击的单段分支，确定数据口径。
2. 一次只改变装备攻击，检查线性贡献，避免 S 与 Ae 重复计入。
3. 分离防御分母、二次衰减和模式修正。
4. 检查属性/暴击组合，不把不同分支混合回归。
5. Slide 比较可观察区间和分布，而不是要求视频某一击等于随机模拟某一击。
6. 分离额外、穿防、护盾/减伤、Fever 分支，再检查叠加顺序。
7. 最后进入点火/增幅/模式专属机制。每次只识别少数未知参数，不能用同一组录像同时反推所有东西。

建立训练/校准集和独立保留验证集，按战斗/角色/条件切分，不能同一录像切帧后两边重复。候选公式失败就记录适用边界，不加一串角色特判去掩盖错误。

有完整输入的确定性样本，可把平均相对误差 ≤3%、P95 ≤5% 作为本项目验收目标；低伤害用绝对误差补充。随机结果用置信区间/分位点/分布检验，并报告样本量。这些是项目门槛，不是对现有公式已达标的宣称。

## G. 随包工具到底能证明什么
`tools/candidate_formulas.py` 只覆盖上面的有限历史候选。测试输入为合成数字，不是伪造的原作战斗记录；输出未套未确认的舍入、最终减伤或 buff 叠加。

工具用于给数值代理一份无歧义参照、防止最初公式抄错。通过全部测试不等于获得 90% 数值还原度。接入 Unity 时需按 C# 的数值精度和目标版逐项加回归测试；不要因为函数返回了一个数就将 UNKNOWN 项改成 VERIFIED。
